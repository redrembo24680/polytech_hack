# Демо-сценарій (4-5 хв, відео або наживо)

Мета: за 5 хвилин показати, що агент **діє, пояснює і кличе людину лише коли так кажуть правила**.
Два екрани поруч (лише сайт): ліворуч клієнт (чат `localhost:3000/b/lumen/support`), праворуч адмінка
`localhost:3000/admin/lumen` з панеллю «Погодження дій агента». Copilot (`localhost:8000`) потрібен лише розробникам, для показу tool-викликів.

## 0. Підготовка (за 30-60 хв до запису)

Порядок запуску (усі шляхи від кореня репо):

1. Платформа тіммейта:
   `cd site && docker compose up -d --build` (перший запуск кілька хвилин).
   Перевірка: `curl localhost:8001/api/health` -> `{"status":"ok"}`.
2. Агент. У `support-agent/.env`: `ANTHROPIC_API_KEY` (оркестратор і воркер, Claude Sonnet 5.5),
   `AGENT_PROVIDER=anthropic`, `ANSWERER_PROVIDER=gemini` + `GEMINI_API_KEY` (або `ollama` з `gemma4:12b`).
   Запуск **протягом дня, а не за хвилину до запису**:
   `cd support-agent && APP_API_URL=http://localhost:8001 uv run uvicorn agent.main:app --host 0.0.0.0 --port 8000`
   (без `APP_API_URL` агент працює на демо-даних у пам'яті, записи там відносні до **старту сервера**:
   завтра о 10:00 лишається "завтра" лише в день запуску, не запускайте за ніч до показу).
3. Чат на сайті йде вебхуком: у `site/.env` `AGENT_URL=http://host.docker.internal:8000`,
   потім `cd site && docker compose up -d backend`.
4. **Скинути демо-дані перед кожним записом**: кнопка "Скинути демо" в адмінці
   (`localhost:3000/admin/lumen`) або `curl -XPOST localhost:8001/api/admin/reset`.
   Час записів у платформі рахується від моменту скидання. Якщо працюєте без `APP_API_URL`, перезапустіть агента.
5. Вікна: ліве `localhost:3000/b/lumen/support` (чат клієнта на сайті); праве `localhost:3000/admin/lumen`
   (адмінка, панель «Погодження дій агента»). Copilot `localhost:8000` (для розробників) за потреби в третій вкладці.
   Автозапис обох вікон: `cd support-agent && uv run python scripts/demo/run_demo.py --scene ALL --headless --admin site --mp4`.
6. Прогрів: одне тестове повідомлення від Олени, потім знову скинути демо (перший виклик LLM найповільніший).
7. Тести перед показом: `cd support-agent && uv run pytest -q` (мають бути зелені).
8. Опційно (голос): див. сцену F.

Чек-лист за хвилину до старту: сервіси відповідають, демо скинуте, панель погоджень порожня, звук/мікрофон,
шрифт збільшено (Cmd +), закриті зайві вкладки і сповіщення.

## 1. Сценарій по сценах

| # | Сцена | Час |
|---|---|---|
| 0 | Вступ: що бачимо | 0:20 |
| A | Олена: автономний goodwill + перенесення | 1:20 |
| B | Максим: апрув людини | 1:20 |
| C | Петро, DentaPlus: повернення, потім скасування | 0:50 |
| D | "Той самий запит, інший бізнес" | 0:20 |
| E | Метрики власника і фінал | 0:20 |
| F | (опційно) голосовий дзвінок | +0:40 |

Разом 4:30 без F. Репетируйте з секундоміром: один хід агента з кількома tools може тривати 10-60 с,
на цей час коментуйте, що відбувається в чаті й адмінці (це і є демо "Reasoning").

### Сцена 0. Вступ (0:20)
Показати два екрани. Сказати: "Ліворуч клієнт салону Lumen Beauty, праворуч адмінка сайту з панеллю погоджень.
Агент не відповідає, а вирішує звернення в межах дозволів бізнесу."

### Сцена A. Олена, автоматично (1:20)
Вибрати `lumen` / `olena`. Написати (розмовна форма, щоб показати розуміння говірки):

> блін, дитина захворіла, не встигаю завтра на 10, можна переставити?

Після «Почати чат» стартова форма показує крок SMS-коду (симуляція підтвердження номера): панель «Ми надіслали SMS із кодом підтвердження на номер +380•••4501», ведучий вводить демо-код `1234` (`NEXT_PUBLIC_SMS_DEMO_CODE`; «SMS» видно в адмінці як повідомлення каналу sms) і натискає «Підтвердити»; лише потім відкривається чат. Агент запускаємо з `VERIFY_PHONE=0`, щоб не питав код вдруге. (У web-UI агента `POST /sessions` кроку немає.)

Журі бачить (для розробників: у copilot), по порядку:
- бейдж тріажу: намір, емоція з інтенсивністю (напр. тривога), регістр (slang), "суть літературною мовою";
- tool-виклики з рішеннями: `get_client_profile` (12 візитів, 0 неявок), `apply_goodwill_exception` -> **Allow** з причиною,
  `find_slots`, `show_card`;
- адміністратор нічого не натискає.
Клієнт бачить: співчутливу коротку відповідь і картку з 3 слотами. Клікнути слот.
Далі `reschedule_booking` -> Allow, клієнт бачить decision-картку: "перенесено, передоплату збережено".
Фраза: "Пізня зміна зазвичай спалює передоплату, але для постійної клієнтки правила дозволяють виняток. Агент сам це зважив і пояснив."

Окремо наголосити: у бейджі тріажу `register: slang` і `normalized` ("клієнтка просить перенести запис через хворобу дитини");
агент відповідає звичайною українською і не копіює сленг. Запасна розмовна фраза, якщо потрібен другий приклад
(після скидання демо): "блін, не встигаю завтра, можна переставити?"

### Сцена B. Максим, апрув (1:20)
Скинути чат (нова сесія), вибрати `lumen` / `max`. Той самий запит:

> Дитина захворіла, не встигну завтра на 10, можна щось зробити?

Журі бачить: профіль з 2 неявками, `apply_goodwill_exception` -> **NeedsApproval** (жовтий статус, причина),
в адмінці сайту (панель «Погодження дій агента», оновлюється кожні 2 с) з'являється **картка**: назва дії, аргументи, причина, кнопки "Схвалити" / "Відхилити" і нотатка.
Клієнт бачить чесну відповідь: "перенести можу, але за правилами передоплата згорить; виняток має підтвердити адміністратор".
Адміністратор: вписати нотатку "ок, разово", натиснути **Схвалити**.
Агент сам продовжує: слоти, перенесення зі збереженням передоплати, decision-картка клієнту.
Фраза: "Людина вирішила одним кліком, а не переписувалась з клієнтом. Контекст не загубився."
Якщо натиснути "Відхилити": агент запропонує перенесення зі згорянням або скасування (можна згадати словами).

### Сцена C. Петро, DentaPlus (0:50)
Вибрати `dentaplus` / `petro`. Написати:

> Хочу скасувати запис і повернути гроші.

Журі бачить: **два** approval-блоки (повернення передоплати і скасування), агент чесно пише клієнту, що чекає адміністратора.
Схвалити **спершу повернення**, потім скасування (порядок важливий, див. README агента).
Клієнт бачить decision-картку: "скасовано, повернено N грн".
Фраза: "Сувора політика клініки: жодних грошових дій без людини."

### Сцена D. Той самий запит, інший бізнес (0:20)
Не набирати нічого нового, показати поруч підсумки: Олена (Lumen) -> Allow без людини; Максим (Lumen) -> апрув;
Петро (DentaPlus) -> лише з апрувом. Сказати: "Один агент, один запит про відмову від візиту, три різні результати:
залежить від правил бізнесу і історії клієнта. Не жорстка автоматизація, а політика + контекст."
Для наочності можна швидко відкрити `localhost:3000/admin/lumen` і `/admin/dentaplus`, де видно різні правила.

### Сцена E. Метрики і фінал (0:20)
У блоці метрик copilot (для розробників): сесії, автономні дії, апруви, ескалації, `money_saved_uah`, розподіл намірів і емоцій.
Сказати: "Власник бачить, що вирішено без людини, де потрібна людина, скільки грошей збережено."
Завершити тагліном із `PITCH.md`.

### Сцена F. (ОПЦІЙНО) Дзвінок (+0:40)
Тільки якщо телефонія **перевірена наживо** (Vapi, див. `support-agent/README.md`, розділ "Телефонія через Vapi"):
запуск `AGENT_PROVIDER=fake ORCHESTRATOR=off uv run uvicorn agent.main:app --port 8000`, `ngrok http 8000`,
`PUBLIC_URL` у `.env`, `uv run python scripts/vapi_setup.py --number`. Зателефонувати з номера з seed
(`+380501110001`), сказати те саме про перенесення; показати, що апрув з дзвінка з'являється в тій самій панелі погоджень,
а картка йде SMS-логом. Якщо хоч раз не спрацювало до запису, **вирізати сцену** і не згадувати голос як готову функцію.

## 2. План B

| Проблема | Що робити |
|---|---|
| LLM повільна (>60 с на хід) | Говорити поверх чату й адмінки (за потреби показати tool-виклики в copilot); заздалегідь записати відео кожної сцени як запас |
| 429 / ключ вичерпано | Другий ключ Gemini; перемкнути `AGENT_PROVIDER`/`ANSWERER_PROVIDER=ollama` (локальна `gemma4:12b`, хід 30-60 с) |
| LLM недоступна зовсім | `AGENT_PROVIDER=fake ORCHESTRATOR=off ANSWERER=off uv run uvicorn agent.main:app --port 8000`: показує лише UI (відповідь "Тестова відповідь", без tools). Сценарії показувати з **попередньо записаних кліпів** |
| Сайт/Docker не піднявся | Показувати чат і copilot на `localhost:8000` без `APP_API_URL` (демо-дані в пам'яті) |
| Чат сайту не відповідає | `AGENT_URL`, `docker compose up -d backend`; запасний варіант `localhost:8000` |
| Мережа/Wi-Fi лягли | Локальна Gemma через Ollama, заздалегідь `ollama pull gemma4:12b` |
| Консольний запасний прогін | `cd support-agent && uv run python scripts/smoke.py --scenario A` (B і C схвалює автоматично) |

Завжди мати: записаний кліп кожної сцени (A, B, C), скриншот approval card і метрик, запущені сервіси з учорашнього дня
не перезапускати без потреби.

## 3. Правила чесності під час демо
- Називати моделі правильно: Claude Sonnet 5.5 оркестрація і виконання дій, Gemma 4 прості відповіді.
- Не казати "Gemma виконує дії". Не показувати голос як працюючий, якщо не перевірено.

# Відомі підводні камені

- Tools відхиляють явний `staff_id: null`: `find_slots` і `reschedule_booking` валідують тип (`string`), тому `null` дає `{"error":"validation"}`. Необов'язковий аргумент треба не передавати зовсім. Це ж стосується будь-якого optional-аргументу.
- Gemma 4 може повертати "thought"-частини. `GeminiClient.generate` збирає в `TextPart` будь-який `part.text`, окремо thought не відфільтровує. Якщо в чаті з'явиться внутрішнє міркування, фільтрувати по `part.thought` у `agent/llm.py`.
- Апрув виконується рівно один раз: `ApprovalStore.decide` під локом переводить статус з `pending` (повторне рішення: 409 `already_decided`), `execute_approved` викликається лише після цього й сам повторно не захищений. Викликати його поза `POST /approvals/{id}/decide` (крім `scripts/smoke.py`) не можна.
- Виконання апруву і `resume_after_approval` йдуть під локом сесії; якщо резюме агента падає, дія вже виконана: відповідь `{"error": {"error":"resume_failed"}}` з `result`.
- Free-tier Gemini API має невідомі денні ліміти й rate limit: при 429 агент віддає подію `error` і текст про технічну помилку (ретраїв з backoff немає). Радимо два ключі та `AGENT_PROVIDER=fake` для запасного демо.
- Багатокрокові tool-ланцюжки в Gemma 4 можуть бути слабшими: якщо модель не викликає tools або ламає JSON, спробувати `AGENT_SYSTEM_AS_PREFIX=1`, потім `AGENT_MODEL=gemini-2.5-flash`. Live-прогін ще не виконано (немає ключа), робочу конфігурацію тут слід зафіксувати.
- `AGENT_PROVIDER=fake` повертає лише текст "Тестова відповідь" без tool-викликів: добрий для перевірки UI/API, але не показує сценарії A/B/C.
- Starlette у тестах друкує попередження про `httpx2` (TestClient); це відомий шум, 96 тестів зелені. Прибрати можна `uv add --dev httpx2`, рішення за власником репо.
- Стан у пам'яті: рестарт скидає сесії, події, апруви й зміни даних; `day_offset` у seed відраховується від `now` на старті.
- Час: усе в `Europe/Kyiv`; `find_slots` будує діапазон у таймзоні `ctx.now`. "Завтра на 10" модель має рахувати від `Поточний час` у промпті.
- Модель бачить лише свої бронювання: чужий `booking_id` дає `not_found`.
- Одне повідомлення за раз на сесію: паралельний запит отримує 409 `busy`.
- `max_iter=8`: після 8 кроків без відповіді агент передає запит адміністратору й емітить `error`.

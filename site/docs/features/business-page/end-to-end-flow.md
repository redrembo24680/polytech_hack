# Наскрізний сценарій

1. `/b/lumen` (серверний компонент) паралельно читає `GET /api/tenants/lumen`, `/services`, `/staff` і рендерить профіль; правила — `policyToText(tenant.policy)`.
2. «Записатись» -> `/b/lumen/book`; сервер знову завантажує ті ж три ресурси й передає їх у клієнтський `BookingFlow`.
3. Вибір послуги -> майстер (лише ті, чий `service_ids` містить послугу, або «Будь-хто») -> день із 7 (сьогодні + 6, за `tenant.timezone`).
4. `GET /api/tenants/lumen/slots?service_id&from&to[&staff_id]`; `from`/`to` — північ обраного та наступного дня з офсетом Києва (`dayBoundary`).
   Для «Будь-хто» слоти різних майстрів зі спільним часом зводяться в один; береться перший майстер зі списку.
5. Ім'я + телефон (будь-який формат) -> `POST /api/tenants/lumen/bookings` з `{client:{name,phone}, service_id, staff_id, start, by:"human:client"}`.
6. 201 -> картка підтвердження: дата й час (Київ), майстер, послуга, сума передоплати (`booking.prepayment.amount`), посилання на сторінку бізнесу.
7. 409 `slot_taken` -> повідомлення «Цей час щойно зайняли», вибір часу скидається, слоти перезавантажуються.

# Наскрізний сценарій

1. Клієнт відкриває `/b/lumen/support`, вводить ім'я й телефон -> `POST /support/conversations {client_name, client_phone}`; `conversationId` іде в `localStorage`.
2. Пише повідомлення -> `POST .../conversations/{id}/messages {text}`. Бекенд зберігає його (`role=client`), потім **синхронно** шле `POST {AGENT_URL}/chat` (до 60 с). Відповідь `{reply}` зберігається як `role=agent`. Відповідь 201 — список створених повідомлень (клієнтське + відповідь агента, якщо є). Весь цей час UI показує «Агент друкує…».
3. Агент (або людина) може дописати асинхронно: `POST .../conversations/{id}/reply {text, role}` або `POST /api/tenants/{t}/messages` з `channel=chat` (потрапляє в останню відкриту розмову клієнта як `role=agent`). Сторінка підхоплює їх опитуванням `GET .../messages?after=<ts останнього>` кожні 2 с.
4. При перезавантаженні розмова відновлюється; якщо вона зникла (404) або закрита — показується форма. Кнопка «Нова розмова» очищає ключ.
